# 首次导入照片 · 产品逻辑 v2

2026-10-29。依据：PRODUCT「首次使用」、白皮书 §2.2 / §5.1 / §5.2，vivo V2502A 真机排查，`claude/earth-home-polish` 现有实现。实现记录见 [FIRST_USE.md](FIRST_USE.md)。

## 一、目标

一位从没用过的人，打开 App → **3 分钟内**看到自己的地球、确认住过哪里。

| 指标 | 目标 | 现在能否测 |
|---|---|---|
| 点"开始"到地球上出现第一个点 | ≤ 10 秒（白皮书退出标准是首城 ≤ 60 秒） | 能（扫描预览点） |
| 全流程（开始 → 首页） | ≤ 3 分钟 | 能，需本地计时 |
| 首次导入完成率 | 记录，Beta 判断 | 需本地指标 |

**三个必须成立的感受**（白皮书 §2.2）：这确实是我的历史 / 原来这段时间也是人生的一章 / 我想再看一次。

## 二、现在的链路与问题

现在一共要经过 **10 个界面或步骤**：空首页 → 导入说明弹窗 → 系统相册授权 → 系统照片位置授权 → 扫描条 → "导入完成"页 → 揭晓 → 自动回放 → 最多 3 问 → 阶段草稿。

| # | 问题 | 依据 |
|---|---|---|
| 1 | **"导入完成"页和揭晓重复**：先说"新增 N 次旅行 · M 个地方"，点"去地球上看看"后又报一次城市、旅行数；多一次点击，还把揭晓的惊喜提前说破 | `photo-ui.js renderAuto` 的 done 状态 + `earth-first-use.js` reveal |
| 2 | **第一次就露出次要入口**：导入说明页底部有"备份与存储 / 高级导入与记录"，新用户既用不到，也分散注意 | `renderAuto` footer |
| 3 | **Android 看不到"扫了多少、有位置的多少"**：原生扫描只回传带位置的照片，揭晓里"另有 N 张没有位置"在手机上永远不出现；GPS 比例低时用户以为"漏了" | `android-auto-import.js` 只收 `page.located`；`scanned` 有总数但未进揭晓 |
| 4 | **零结果是死路**：一张带位置的照片都没有时，首次使用不会启动，只显示"没有发现新的足迹"——对新用户是误导（常见原因：相机没开定位、相册里多是微信保存图或截图） | `prepareFirstUse` 要求有照片记忆；done 文案 |
| 5 | **"部分照片"授权没有说明**：Android 14+ 用户若只授权部分照片，只会扫到那几张，结果偏少却没有任何提示 | `MediaLibrary.photos()` 返回 `limited`，前端未用 |
| 6 | **拒绝授权的出路弱**：报错文案能看懂，但没有"去设置"按钮，也没有"先看示例" | `ensureLocationAccess` 错误文本 |
| 7 | **扫描中只有点、没有名字**：点亮已经有了，但"成都、上海…"这类城市名要等到最后才出现；扫描后半段（整理地名）没有新的视觉进展 | `nameCells` 有逐个进度，未回传名字 |
| 8 | **中途退出全部重来**：取消或切走后，下次从头读；大相册（5k+）代价高 | Android checkpoint 只在提交后保存 |
| 9 | **"先看地球"会永久跳过剩余问题**，按钮名字没说清后果；之后只能从"我的 → 确认居住与人生阶段"回来 | `finish()` = `skip()` + `finish()` |

## 三、v2 流程

```
空首页 ──「从相册开始」──▶ 说明页（一屏，单一主按钮）
                              │
                              ▼
                       系统授权：相册 → 照片位置
            ┌─────────────────┼──────────────────┐
         拒绝 / 不再询问     部分照片            全部授权
            │                 │                    │
     授权引导页            扫描（标注"仅已选照片"） 扫描
   [去设置] [看看示例]          └─────────┬──────────┘
                                          ▼
                     扫描条 + 地球逐个亮点 + "已发现：成都、上海…"
                                          │
                 ┌────────────────────────┼─────────────────────┐
             0 个地点                  1–2 个城市              ≥ 3 个城市
                 │                        │                      │
         零结果说明页               揭晓（如实说明比例）     揭晓（直接进入，无"导入完成"页）
   [查看如何开启相机定位]                  └──────────┬───────────┘
   [换一批照片] [看看示例]                            ▼
                                        自动回放约 20 秒（减少动态时不自动）
                                                      ▼
                                       最多 3 问（现居 → 曾居）
                                                      ▼
                         多段居住 → 给阶段起名   ·   以旅行为主 → 年度回顾   ·   其他 → 首页
```

### 每一步的规则

**说明页**（首次导入专用，再次导入沿用现在的简版）
- 标题：从相册开始。正文两句：原图不上传、不复制；需要读取拍摄位置，用来把照片放到城市上，不会持续定位。
- 只有一个主按钮。"备份与存储 / 高级导入"只在已有数据后出现。

**授权**
- 顺序不变：相册 → 照片位置（系统要求分开申请）。
- 拒绝：进入授权引导页，按钮"去系统设置"（Android 打开应用权限页）+ "先看看示例"。
- 部分照片：照常扫描，扫描条和揭晓都写明"只读取了你选择的 N 张照片"，并给"授权全部照片"入口。

**扫描**
- 读取阶段：地球上按城市粒度逐个亮点（已实现），文字"正在读取照片 1,234 / 5,000 · 已发现 7 个地方"。
- 整理地名阶段：把刚解析出的城市名依次显示在条上（最多显示最近 3 个），让后半段也有进展。
- 可取消；取消不写入任何记录（已实现）。Android 断点续扫列为 P1（需要可续扫的观测缓存，单独设计）。

**结果分支**（首次导入时跳过"导入完成"页，直接进揭晓或说明页）
- **0 个地点**：零结果说明页——"读取了 N 张照片，但都没有拍摄位置"，常见原因（相机定位关闭、微信保存图片和截图不带位置），两个按钮：查看如何开启相机定位（简短图文，不跳外部网页）、看看示例。不生成首次使用进度，下次导入仍按"第一次"处理。
- **1–2 个城市，或带位置的照片低于 20%**：正常揭晓，但说明写成"5,000 张照片里有 312 张带位置"，并提示开启相机定位后再导入会更完整。
- **≥ 3 个城市**：正常揭晓。

**揭晓**
- 数字：城市、旅行、国家 / 地区；下面一行写清来源："读取了 N 张照片，M 张带位置"（Android 也要有，需原生扫描回传总数与带位置数）。
- 按钮：确认居住地 · 最多 3 问（主）、回放、先看地球。

**问答**
- 规则不变（最多 3 问、可撤销、刷新续答）。
- "先看地球"改为"跳过，直接看地球"，并在下方小字说明"之后可在「我的」里继续确认"。

**去向**
- 不变：多段居住 → 给阶段起名；以旅行为主 → 生成某年年度回顾；否则回到地球。

## 四、不变的原则

- 推断不冒充观测；没有位置的照片不编造城市；取消扫描不留半份数据。
- 所有自动结果可改、可撤销；"重新整理"不覆盖人工修改。
- 原图不上传；地名默认离线解析，不发网络请求。
