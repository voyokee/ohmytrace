## 0. 执行摘要

### 0.0 愿景与一句话定位

OnceHere 是融合真实地理、人生时间轴与个人记忆的沉浸式 3D 人生地图——**个人空间传记平台（Personal Spatial Biography Platform）**。

对用户的一句话（PRODUCT）：

> **用照片自动还原你住过、去过的地方，再按人生阶段重新走一遍。**

核心理念：从"记录去过哪里"升级为"重新体验走过的人生"。足迹是入口，人生阶段是纵深，故事是传播。

### 0.1 八项原则（不变）

1. **Truth before beauty**：观测、推断、人工三者必须区分；推断路线不得画成 GPS 实测轨迹；缺少 GPS 不编造坐标。
2. **Time as first-class data**：人生阶段可命名、编辑、重叠和关联，不是年份筛选的装饰。
3. **Local-first by default**：个人历史本地保存、可备份、可迁移；云服务永远是明确选项，不以账号作为访问个人历史的前提。
4. **Capture once, render many**：导入、规范化 Life Graph、3D 渲染派生数据彻底解耦。
5. **Progressive experience**：导入未结束时就尽快呈现可解释的个人地球。
6. **One coordinate system, multiple expressions**：WGS84 语义坐标稳定；全球微缩与近景地形可采用不同艺术尺度。
7. **User correction beats algorithmic confidence**：用户确认的事实优先；不覆写历史，留下修订来源；"重新整理"不覆盖人工修改。
8. **Share deliberately**：分享的是用户批准后的缩减视图（Share Projection），绝不是数据库的公开链接。

v1.1 对原则 7 的落实方式有变化：由"导入前先审核"改为"所有自动结果标注来源、可就地修改、可撤销"（ADR-007）。

### 0.2 六项核心能力与现状

| 能力 | 目标 | 2026-10-28 现状 |
|---|---|---|
| **Living World** | 真实 DEM 与 WGS84 上的风格化地球；全球 → 区域 → 旅行 → 地点连续飞行；植被、雪、雾、光照随季节、纬度、海拔与生态变化，遵循基本气候规律，真实资料与艺术推断分开 | 30× 全球微缩地形、真实地形飞入、七类程序化 GLB 植被、季节模板、GPU Instancing、LOD、Worker、自适应画质。高山大视口未持续达到帧率目标；无真机帧率 |
| **Life Timeline** | Overview → Year → Life Chapter → Trip → Day/Place 五级；与地球双向联动；播放、暂停、跳转、调速 | 全部 / 年份筛选、年 / 月聚合、旅程回放、调速播放器、首次短回放。人生模式（阶段色带）与双向联动在 ROADMAP I4 |
| **Memory Reconstruction** | 照片 EXIF、GPS、CSV、GPX、KML、GeoJSON、手动；识别到访、旅程、居住、路线；可确认、修改、合并、拆分、撤销 | Web EXIF（JPEG / HEIC / PNG / WebP）、ZIP / 目录、万张规模；Android MediaStore 一键导入与增量续扫；离线城市命名；居住推断；路过 / 转机推断。GPX / KML / GeoJSON 导入未做 |
| **Life Graph** | 统一规范模型、稳定 ID、证据溯源；支持不完整日期、重叠章节 | IndexedDB schema v1：七个集合、Evidence 四态、修订记录、Legacy 迁移、统一备份。RouteSegment 与 Chapter 嵌套未做 |
| **Life Story** | 年度 / 旅程 / 阶段作品；互动链接、回放、短视频、海报；隐私预览、权限、撤销 | 故事编排、隐私审查、静态 ZIP、托管分享（私密 / 不公开链接 / 公开）、可撤销、独立 Viewer、一键分享面板。短视频 / 海报未做；托管服务不适合国内（§16.4） |
| **AI Life Narrator** | 基于授权证据的可信叙事，标注事实与推断 | 未开始，P3 |

### 0.3 最终目标

完整闭环：**发现经历 → 重建可信足迹 → 组织人生章节 → 沉浸式回望 → 创作故事 → 分享与长期保存**。

短期让用户不学 CSV 就能拥有自己的地球；中期让用户愿意反复回来给人生阶段起名、补照片、分享；长期成为可终身使用、拥有并传承的个人空间传记系统。

### 0.4 当前最关键的三件事

1. **真机证据为零。** Android 导入吞吐、HEIC、真实相册规模、WebView 帧率与 IndexedDB 持久性都未在真机测过（ROADMAP §2）。
2. **国内上架有硬性阻断项。** 离线地名数据把台湾的国家名写成"中华民国"、港澳按独立国家统计；分享托管依赖境外服务与 ChatGPT 登录；尚无 APP 备案、隐私政策与审图方案（§13.3）。
3. **品牌名称未清理。** App Store 已有名称相近的足迹 App「Once Here（曾在）」（§6.2）。

# 第一部分｜产品战略与用户价值

## 1. 愿景、任务与类别

**Vision**：让每个人都拥有一颗承载自己人生的地球，时间不再只是照片列表中的日期，而是一条可以亲自走回去的路。

**Mission**：把散落在相册、照片 EXIF、GPS 文件、旅行记录与记忆里的碎片，转换成用户自己拥有、可以核验和编辑的 Life Graph，再投射为可探索、可回放、可传承的空间故事。

**类别**：个人空间传记平台，而不是旅行规划工具、GPS 记录器、云相册或 3D 地球壁纸。

**品牌叙事**：Place → Trace → Memory → Chapter → Story。地点是坐标；足迹是经历过的证据；记忆是人、图像、文字与情绪的上下文；章节把事件组织成有意义的人生阶段；故事使之可以被重新体验与分享。

### 1.2 用户要完成的工作（JTBD）

- **回忆过去**：过去几年分别在哪里生活、旅行，不必翻几万张照片。
- **整理迁移**：人生不是单一城市时间轴——可能在外地读书，暑假去另一座城市实习，中间还有旅行。
- **讲给别人听**：把"一段人生"或"一年"分享给家人、伴侣、朋友，而不只是几张图或一张点亮地图。
- **保留控制权**：愿意授权读照片，但不愿意无意间公开住址、精确日期或私密照片。
- **长久可携带**：换手机、服务停止或不再付费时，历史和故事仍然在自己手里。

**反向界定**：不做"帮我规划下次旅行"；不要求持续后台追踪；初期不做无限原图云相册。

## 2. 目标用户与使用场景

### 2.1 第一批用户（国内优先）

| 人群 | 他们来做什么 | 我们先满足 | 优先级 |
|---|---|---|---|
| **A. 多城生活的年轻人**（求学、换城市工作、异地） | 回看某段人生在哪、做了什么 | 自动推断居住阶段 → 起名 → 阶段回放 | 首要 |
| **B. 旅行爱好者** | 点亮去过的地方、统计、炫耀 | 一键点亮，国家 / 地区、城市、旅程数字，年度回顾分享 | 首要 |
| C. 回忆与叙事创作者 | 年度、情侣旅行、毕业阶段作品 | 选照片、回放、分享 | 次要 |
| D. 家庭与代际记忆 | 家庭迁居、共同经历 | 共享章节、共同补录 | 后期 |
| E. 高校 / 博物馆 / 机构 | 人物或群体迁移的交互展陈 | 空间叙事项目授权 | 探索性 B2B |

A、B 走同一条首次使用路径，区别只在首页之后：有多段居住的被引导给阶段起名，以旅行为主的被引导生成年度回顾（PRODUCT）。

v1.0 的 B 是"长期旅行 / 户外记录者"，看重 GPX 与路线真实性。v1.1 改为以相册为主的旅行爱好者，因为照片导入是两类人的共同入口；GPX 仍作为开放导入导出格式保留（导出在 ROADMAP I2，导入在 Beta 0.3 之后），户外轨迹用户不再是首批设计对象。

### 2.2 北极星体验

授权相册 → 扫描中城市逐个在地球上亮起 → 揭晓"几个国家 / 地区、几座城市、几次旅程"并自动回放约 20 秒 → 回答最多 3 个问题得到人生阶段草稿 → 点开"在成都的那六年"，镜头从常驻城市出发，穿过其间的旅程和照片 → 选择隐私范围分享给朋友。

三个必须成立的情绪时刻：**"这确实是我的历史"**、**"原来这段时间也是我人生的一章"**、**"我想再看一次，也愿意让别人看见一部分"**。点击不是证据；复访、修正、起名、分享与付费才是。

## 3. 核心产品模型与信息架构

### 3.1 用户概念与系统对象

用户只需要理解三样东西（PRODUCT）；系统内部仍维护完整的 Life Graph：

| 用户概念 | 系统对象 | 用户能做的事 |
|---|---|---|
| **城市** | Place / PlaceVisit | 看照片、改名、改为路过 / 转机、合并 |
| **旅程** | Trip（v2 增加 RouteSegment） | 回放、看照片、拆分 / 合并、改标题、分享 |
| **人生阶段** | ResidencePeriod + LifeChapter | 系统先推断"住在哪、什么时候"，用户起名、回放、分享 |

Memory、Evidence、Visit、JSON、CSV 不出现在主流程。证据与推断只以"这是推断的（依据……），点一下可以改"的形式露出。

**Chapter 不是日期查询。** "2025 年去过哪里"只是筛选；Chapter 必须有独立的 ID、标题、类型、时间、锚点和关系，能被命名、编辑、重叠和分享。

### 3.2 信息架构

```
OnceHere
├─ 首页：地球 + 一行摘要（旅程 · 城市 · 在路上天数 · 现居）
│   └─ 底部时间轴：人生（阶段色带 + 旅程点） / 年份（年 / 月聚合）
├─ 统一底部卡片（城市 / 旅程 / 阶段共用）
│   └─ 回放 · 照片 · 分享 · 不对？（就地改名、改类型、合并、拆分、删除，可撤销）
└─ 工具栏
    ├─ 分享
    ├─ 添加照片
    └─ 我的：备份与恢复、导入导出（CSV / GPX / JSON 归入"高级"）、夜景、隐私说明
```

所有入口读写同一份 Canonical Life Graph。地球、时间轴、卡片、故事编辑器都是投影，不各自维护一份真相。3D 场景（近看、植被、季节）是氛围与惊喜，不承担操作入口。

### 3.3 空间与时间尺度

**空间四级**：World（人生地理范围）→ Region（国家、城市群、山地海岸）→ Trip（停留顺序与日期，真实性优先）→ Place（照片、注记、季节化近景，艺术层不伪装实景）。由连续镜头组织。

**时间五级**：Overview → Year → Life Chapter → Trip → Day/Place。这是数据模型与回放必须支持的能力。界面在 Beta 0.3 只暴露"人生"与"年份"两种时间轴模式，Chapter 与 Trip 通过色带和点进入，Day/Place 完整视图放到 0.3 之后。时间与相机双向联动：选时间则镜头定位；在地球上点城市可反查所属阶段与到访历史。

## 4. 功能规格

### 4.1 F01｜多源历史导入（P0）

目标：把门槛从"理解 CSV 格式"降为"授权相册，得到可纠正的结果"。

| 要求 | 现状 |
|---|---|
| Android 读取系统相册，一键导入、增量更新、可中断续扫 | MediaStore 分页、权限与日期范围、持久化续扫检查点、原生 HEIC 缩略图；真机未验收 |
| Web 用户显式选择照片 / 文件夹 / ZIP，读取 EXIF | JPEG / HEIC / PNG / WebP、ZIP、目录、万张规模已验证（合成数据） |
| 原有 CSV 双向兼容（中英文表头、GBK、粘贴） | 保留 |
| GPX / KML / GeoJSON 导入 | 未做；GPX / GeoJSON 导出在 ROADMAP I2，导入在 Beta 0.3 之后 |
| 渐进展示，长任务可暂停 / 恢复 | 自动导入后揭晓；"扫描中城市逐个点亮"在 ROADMAP I5 |
| 缺少 GPS 不推断精确坐标 | 无地点照片保留记录，不编造城市或旅行 |
| 重复照片、HEIC、时区、修改时间的兼容策略 | 重复导入不产生重复实体、照片 ID 保留已验证；国产相机写入坐标系待真机样本核实（§13.3） |

验收：有位置照片生成城市；每个推断旅程可编辑；退出重开可恢复或安全重试；同一文件重复导入不产生重复实体。首入成功率目标 ≥ 65%（假设，需真实用户验证）。

### 4.2 F02｜Life Chapter（P0 数据、P1 体验）

字段：标题、类型（学习 / 工作 / 旅行 / 家庭 / 自定义）、起止、描述、城市锚点、关联旅程与记忆、可选父章节（v2）、分享可见性。允许重叠，不要求全人生无缝分割。

v1.1 的来源规则：

- 已确认（或未被否认）的居住时段生成**中性草稿**，例如"成都的日子"，标记为草稿；用户起名即确认。
- 系统不从照片内容猜测学校、职业或亲密关系；只基于居住锚点与用户输入建议中性标题。
- 用户仍可手动建立任意章节。

典型案例：外地读研 2024.08–2026.01 与北京实习 2025.05–08 可以重叠；实习期间的一次旅行可同时关联两个章节。

验收：建立重叠章节不报冲突；单个旅程可被多个章节引用；删除章节不级联删除旅程或照片；能从章节追踪到每条事实来源。现状：CRUD、城市锚点、关联、重叠已实现；嵌套（`parentId`）在 schema v2。

### 4.3 F03｜可信地点与路线（P0）

位置来源（照片 GPS、GPX、用户选择、地名查询）、精度与"观测 / 推断 / 人工"在卡片上露出，例如"按 2023 年 41 个拍照日推断为常驻"。用户可在"不对？"里改名、改类型（旅行 / 路过 / 转机 / 现居 / 曾居）、合并、拆分、删除（隐藏），均可撤销。

旅程相邻地点的连线是示意（虚线）；只有真实轨迹数据才画实线。v2 的 RouteSegment 把"实测轨迹 / 推测连接"变成数据，而不仅是渲染样式。

验收：图例区分实测与推测；更正城市不改写原始 EXIF 观测；可恢复上一版本。现状：编辑命令、撤销 / 重做、统一卡片已合入（[TRUSTED_EDITS.md](TRUSTED_EDITS.md)），自动化与桌面浏览器已验证。

### 4.4 F04｜人生时间机器（P1，数据模型 P0）

人生模式下，居住阶段为色带、旅程为点，色带可起名、可重叠显示；年份模式保留现有筛选与年 / 月聚合。阶段、年份、旅程都能播放、暂停、跳转、调速；阶段回放串联常驻城市、旅程与照片。切换过滤时取消过期回放任务。

验收：切换粒度不丢对象；跨年旅程在各交集年份正确计数；回放暂停 / 跳转状态确定；镜头生命周期有 cancel / cleanup。排期见 ROADMAP I4。

### 4.5 F05｜Living World（持续增强）

保留全球微缩地形、夜景足迹与近景真实地形。季节表达拆为日期语义、气候先验、区域生态、艺术风格四个输入：中国南方冬季不因 12 月统一盖雪，高海拔可积雪，南北半球季节相反。视觉须有"艺术化场景"标识，不暗示旅程当日的真实天气。

验收：同一地点不同季节可复现；无地形 / 影像网络时降级为静态地球或简化地图；支持减少动态效果（首次短回放已遵循）。

### 4.6 F06｜Memory 与叙事编辑（P1）

Memory 可挂在到访、旅程或章节上；一张图可被多个实体引用但只存一份媒体指纹。支持封面、短注、顺序、高光与私密级别。AI 只能在证据范围内辅助起草，不自动发布私人内容。文字 / 语音记忆的关联编辑在 Beta 0.3 之后。

### 4.7 F07｜分享与导出（P1）

分享通过独立的 Story Artifact 输出：只读版本、撤销策略、隐私预览。三类形态：互动链接、竖屏 15–30 秒短视频、海报 / 长图。Viewer 首屏不强制加载完整地形与植被，弱设备逐级升级。

导出：Life JSON（完整保真）、CSV、GeoJSON、GPX（v2）、media manifest、统一备份。

验收：分享页不能读取未公开原始资源；撤销后新访问拿不到托管资产（已下载副本无法追回）；精确地址默认不可见。

现状：互动链接、隐私审查、静态 ZIP、托管分享、撤销已实现；短视频 / 海报未做。国内传播以微信为主，海报 / 长图的优先级应高于 v1.0 的判断（§16.4）。

## 5. 用户旅程与操作契约

首次使用的六步流程、首页、持续使用（增量导入提示新旅程、年度回顾、搬家后提示给上一段起名、备份提醒）以 [PRODUCT.md](PRODUCT.md) 为准，目标 3 分钟内完成。

### 5.1 三条入口

- **相册用户（主路径）**：Android 授权相册与照片位置 → 自动整理 → 揭晓与短回放 → 最多 3 问 → 首页。GPS 命中率低时如实说"找到了 N 张带位置的照片"，不假装完整还原。
- **Web 用户**：手动选择照片 / 文件夹 / ZIP，之后与 App 同样的轻确认，不再逐项审核。高级逐条审核保留在"高级导入与记录"。
- **已有 CSV 的老用户**：导入 → 校验 → 地球；老数据零损失。

无数据访客的示例地球必须明确标注为虚构，与个人数据隔离。

### 5.2 操作契约

对任何自动结果都能回答三件事：**知道什么**（观测）、**推断了什么**（假设及依据）、**缺什么**（未知）。照片默认不上传；"我的"里明确显示本地备份状态；章节重叠不被识别为重复；一座城市可以同时是"曾居地"和多次"旅行"目的地；路过 / 转机不计为旅行。

### 5.3 不做的诱人功能

P0–P1 不做：旅行规划 AI、关注 / 动态式社交、持续耗电轨迹记录、无限原图云相册、复杂机构权限矩阵、全自动"人生意义"生成。

## 6. 竞争格局与品牌

### 6.1 竞争坐标

v1.0 基于 2026-10-26 的竞品研究（Wimemo、Polarsteps、MeTrail、Day One、Driftlog、PhotoTrail、Rond、圆周旅迹、Trip Atlas）：

| 方向 | 他们的优势 | 我们不能误判的 | 我们的主攻点 |
|---|---|---|---|
| Wimemo / PhotoTrail | 照片快速重建旅行 | 照片导入是基础能力，不是壁垒 | 快速导入 + 阶段语义 + 空间叙事 |
| Polarsteps | 路线、旅行回顾、规模 | 3D 地图本身不独占 | 从旅程扩到跨人生阶段 |
| MeTrail / Rond | 日常记录、按居住城市分段、本地数据 | "按城市分段"不是空白市场 | 可命名、可重叠的语义化阶段 |
| Day One | 日记与长期信任 | 好看的地图不能代替记忆质量 | 地理与人生叙事的组合 |
| 圆周旅迹 | 规划与协作 | 不和规划工具比功能 | 旅行之后、旅行之外的长期回望 |

防御方式不是比对手多种树，而是 **无摩擦导入 × 可溯源 × 语义化阶段 × 沉浸体验 × 可控分享** 的整体体验。

**v1.1 待补**：国内优先后，需要补一轮国内足迹 / 点亮类 App 的竞品研究（功能、定价、分享形态、上架主体），v1.0 的竞品集以海外为主，不足以支撑国内定价与定位（§23）。

### 6.2 品牌名称风险

2026-10-26 App Store 核查发现已存在「Once Here（曾在）」旅行足迹 App，定位同样包括照片 GPS → 地图足迹。OnceHere 可用于内部与 Beta；**公开上架前**必须完成商标（含国内商标类别）、应用商店、域名检索，并准备备选名称。中文名同样需要检索，不能使用"曾在"。这是品牌发布 Gate（§21.3 Gate D）。

## 8. Canonical Life Graph

### 8.1 现行 schema v1

`src/life/schema.js`，`SCHEMA_VERSION = 1`。数据集 = `{ schemaVersion, id, revision, meta, ...collections }`，写入经 Repository 写队列、版本校验与写后读回校验。

| 集合 | 要点 | 关键约束 |
|---|---|---|
| `places` | 地名、坐标（可为空）、行政归属与命名来源、合并记录；可带 `visitType` | 地点不含到访日期 |
| `visits` | 某次到访：地点、起止、所属旅程（可空）、原始 CSV 行 | 同地可多次到访 |
| `trips` | 标题、起止、停留（`visitIds`）；可带 `visitType` | 两个地点不必然产生真实路线 |
| `residences` | 现居 / 曾居（`kind`：`home` / `past`）、地点、对应到访、起止、`userConfirmed` | 对应到访不属于任何旅程，地点一致 |
| `chapters` | 标题、类型、起止、`homeAnchors`、`relatedTripIds`、`memoryIds`、`draft`（inferred / confirmed） | 可重叠、多对多；删除不级联 |
| `memories` | 照片、笔记等，关联地点与旅程 | 不要求照片都有 GPS |
| `evidence` | `state`：`observed` / `inferred` / `manual` / `unknown`；`source.kind`；修订前后值 | 可追溯，不静默改写 |

`visitType` 取值为 `travel` / `pass-through` / `transit` / `home` / `past`；路过与转机不计为旅行。

**ID**：`<kind>_<UUID v4>`（`crypto.randomUUID()`）。源文件识别用内容指纹，与业务 ID 分离；不用地名、经纬度或时间做主键。v1.0 建议的 UUIDv7 不再要求——可排序性目前没有使用场景。

**删除**：卡片里的"删除"是隐藏（`hidden: true`），原始实体、ID 与照片观测保留，可撤销；隐藏的自动旅程在重新整理后继续隐藏。用户必须能在"我的"里彻底删除导入缓存与派生结果（待补，§14.2）。

### 8.2 时间语义

日期是 `{ precision, value }`：`precision` ∈ `day` / `month` / `year` / `unknown` / `ongoing`。

- 只有年份的记录只承诺年粒度，不生成虚假天数；未知日期就是 `unknown`，不用 `2024-06-01T00:00Z` 冒充。
- "至今"用 `ongoing` 表示，计算时取当前时刻，不把当天日期写进数据。
- 区间计算：开始取该精度的下界，结束取该精度的上界（含当月 / 当年最后一天）。v1.0 建议的半开区间 `[start, end_exclusive)` 是等价的计算方式，不再要求改存储格式；跨年、交集统计的正确性由测试保证。
- 时区：照片可能只有本地时间或缺少时区，不默认为用户当前时区。时区字段的规范化是 v2 待办。

### 8.3 Truth Model

现行四态（observed / inferred / manual / unknown）加 `source.kind`（如 `geocoder`、`coordinate-correction`、`chapter-editor`）已能表达 v1.0 要求的区分：设备观测、用户声明、时空推断、未知。人工更正是一条带前后值的 Evidence 修订，不用 `confidence = 1.0` 混淆"用户声明"和"设备观测"。

首版 UI 只用三种措辞：**照片记录 / 推断（附依据） / 你改过**。不向用户展示未经校准的概率；只有在独立标注集上完成校准后才考虑显示数值置信度。

**schema v2（Beta 0.3 之后，ROADMAP §6）**：

- `routeSegments`：`from` / `to`、可选几何、`truthClass`（实测轨迹 / 推测连接 / 示意）、交通方式（默认 unknown）、证据 ID、给用户的说明（如"地点顺序已知，实际经过路径未知"）。
- Chapter `parentId`（嵌套）。
- 迁移前自动备份，带回滚测试。

### 8.4 合并、纠错与删除

重复文件按稳定指纹去重。同名不同坐标的地点不自动合并；Place 与 Visit 分别纠错。合并时第一条记录保留 ID，所有关系重定向并去重；拆分时原旅程保留 ID、新旅程分配新 ID。删除章节只删章节与引用边。撤回相册权限不应摧毁用户选择保留的元数据。

## 9. 历史重建算法

### 9.1 管道（现状）

```
相册枚举（Android MediaStore 分页 / Web 文件）
  → 读取拍摄时间、GPS（无 GPS 的照片保留记录，不参与地点）
  → 离线行政区 + 城市归属（WGS84；沿海与边境修正）
  → 按城市归并为到访
  → 居住推断（按拍照日与时段分布判定现居 / 曾居）
  → 旅程切分（相对居住地的离家片段，72 小时间隔规则）
  → 机场 / 路过推断（大型机场附近、停留短 → 路过或转机，不计旅行）
  → 附加照片与 Evidence
  → 阶段草稿（来自居住时段）
  → 最多 3 问轻确认；之后可在卡片上就地纠错
```

元数据分块消费、增量落库，全量照片不进内存。分组算法带版本号（当前为 4）；升级后用户可"重新整理足迹"，人工改名、分类、合并、拆分都受保护（[BORDER_TRANSIT_FIX.md](BORDER_TRANSIT_FIX.md)）。

### 9.2 Trip 识别原则（不变）

不能把"相邻照片间隔小于 X 天"直接当作一次旅行。分层推断：照片 → 候选到访 → 居住锚点 → 相对居住地的候选旅程 → 旅程（命名与包含城市）→ 阶段建议。保留 unassigned；不虚构轨迹几何；阶段建议只基于可靠居住锚点，不猜学校、职业、关系。

**v1.1 的变化**：最终"由用户确认边界"从导入前的必经步骤变为导入后的可选纠错（ADR-007）。为了不让"推断冒充事实"，三条规则同时成立：每个自动结果显示来源；任意修改可撤销；重新整理不覆盖人工修改。

先用规则 + 明确阈值 + 可解释 UI；拿到有授权的标注数据后，才考虑训练概率模型。

### 9.3 核心反例集（必须进入回归测试）

| 反例 | 状态 |
|---|---|
| 同城本科四年中多次外地旅行，不能把四年当成一次旅程 | 由居住推断 + 离家切分覆盖 |
| 远程实习与在读阶段重叠，不能拆断主阶段 | 章节可重叠；居住与章节分离 |
| 跨时区 / 日期变更线，不能出现负旅行天数 | 待补测试 |
| 半年只有少量带 GPS 照片，不能填满未观测日期 | 不编造；需补稀疏样本测试 |
| "厦门转机未出机场"与"厦门旅行"不同 | 机场 / 路过推断 + 路过、转机类型已实现 |
| 返乡、探亲与曾居城市重复出现，不能判为迁居 | 待补测试 |
| 坐标误落海洋、经纬度颠倒 | 沿海归属修正已做；颠倒检测待补 |
| 自驾只有两端照片，画示意不画"实测公路" | 推测连接为虚线；RouteSegment 在 v2 |
| 深港、边境与沿海照片归属 | 已修正并有固定坐标测试 |

## 10. 存储、备份与跨平台

### 10.1 现状

- **Web / WebView**：IndexedDB 规范库（schema v1，事务、校验、写后读回）+ 媒体库（照片观测与缩略图）。localStorage 只留 UI 设置与旧数据迁移入口。
- **备份**：统一备份（Life Atlas JSON + 媒体指针）可在本机恢复。跨设备恢复时原图不在本机，需明确标记（ROADMAP I2）。
- **Android 原图**：保留系统相册引用，不复制几万张原图。

### 10.2 缺口（ROADMAP I2）

- 规范库与媒体库的写入不是原子的，需要检查点或补偿。
- 未调用 `navigator.storage.persist()`；无备份提醒。
- WebView 中 IndexedDB 在卸载、清数据、覆盖安装时的行为未在真机验证。
- 需要在"我的"展示上次备份时间、大小与恢复验证情况。IndexedDB 不等于永久备份。

v1.0 提出 Native 侧用 SQLite。v1.1 判断：Android 是 WebView 壳，语义数据继续放在 WebView 的 IndexedDB 里，原生侧只管相册索引与续扫检查点；只有真机证明 WebView 存储不可靠时，才把规范库迁到原生 SQLite。

### 10.3 云同步

P3，且只在 Beta 证明有跨设备需求后启动。设计按 [CLOUD_SYNC.md](CLOUD_SYNC.md)：快照同步、服务器端 CAS、三方合并；同一实体冲突保留双方由用户处理；墓碑防复活；人工修正不被后到的推断覆盖；不做全系统 CRDT。国内优先意味着同步服务也必须境内部署（§13.3）。

### 10.4 开放格式与可逆性

导出包：`life.json`（完整保真）、`places.geojson`、`routes.gpx`、`media-manifest.json`、`manifest.json`（schema 版本与哈希），CSV 继续开放。GPX / KML 无法表达重叠章节和编辑证据，所以 JSON 是完整格式，标准地理格式供外部工具使用。验收："导出 → 全新安装 → 导入 → 比较"实体与 ID 零差异。

## 11. 地球渲染引擎

### 11.1 保留单 CesiumJS 引擎（ADR-001，不变）

已有 WGS84 连续相机、真实影像与地形、全球展示球壳、Instancing、LOD、相机状态与回放。换 Three.js 要重新付出坐标、相机、地形精度、瓦片缓存和资源生命周期的成本。风格化地球作为同一相机与坐标上的展示层，不做双引擎叠加。

### 11.2 分层场景

```
World（艺术化）   历史影像 + 全球 DEM + 30× 风格化起伏 + 海洋 + 森林实例 + 云与大气
      ↕ 相机 / WGS84 锚点 / 地形交接
Region           按距离交接地形 + 区域森林（默认关闭）
      ↕
Local            真实 DEM 与卫星影像，约 1.65× 夸张 + 近景植被 + 雾与粒子
      ↕
Place & Memory   照片点、注记、统一卡片
```

30× 是远景美术夸张，不是海拔；近景采用接近真实的夸张。

### 11.3 生态与四季

`world-elevation` / `world-surface`、`world-biomes` / `world-forest`、`instanced-vegetation`、`scenery-manager` 等模块已实现（[GOAL_AUDIT.md](GOAL_AUDIT.md)、[MICRO_WORLD.md](MICRO_WORLD.md)）。影像颜色只能粗略推断植被，不等于独立分类的土地覆盖数据，更不等于旅行当天的状态。

```
SeasonState = f(纬度, 海拔, 日期, 半球, 生态类型, 气候先验, 艺术风格, 用户覆盖)
```

视觉主题与"当天真实天气"分开；用户调整主题不影响 Life Graph 的事实。将来若引入历史气象，作为新的 Evidence 来源并标注时空精度。

### 11.4 SceneSlice

渲染器不读取几万条照片元数据，也不每帧重新聚类。SceneSlice 按镜头范围、时间范围、画质档位从 Life Graph 派生，缓存键为 `(dataset_revision, time_scope, camera_bucket, quality_tier, style_version)`；修改章节只让相关投影失效，不重建地球纹理与森林。现状：`renderer-adapter.js` 已承担投影职责；正式 SceneSlice 在 ROADMAP I3。

### 11.5 性能治理

已有：桌面 60 FPS / 窄屏 30 FPS 自适应目标、静止按需绘制、后台暂停、Worker、影像并发 4 / 模型并发 2、植被候选预算、GPU Instancing、分块与 LOD 交接。

| 预算 | 目标（Beta 0.3 退出标准 / 假设） | 观测方式 |
|---|---|---|
| 首个城市出现在地球上 | ≤ 60 s（1k 与 5k+ 真实相册） | 导入分段计时 |
| 完整首次使用 | ≤ 3 分钟 | 首次使用计时 |
| 冷启动可交互 | p75 ≤ 5 s（假设，中档机良好网络） | 本地记录 |
| 全球视角帧率 | 中档机中位数 ≥ 30 FPS，记录 P95 帧间隔 | 真机 trace |
| 内存 | 10k–100k 元数据下不持续增长 | 内存快照 |
| 长任务 | 导入不阻塞主线程数秒 | Long Tasks |

已知问题：高山 / 区域场景未持续达标；瓦片冷加载曾测到 738 ms 帧。"模拟手机画质 30 FPS"不等于真机达标；只看均值没有意义，必须记录 P95 / P99 帧间隔、冷缓存着色器编译与 OOM。

## 12. 平台路线（v1.1 重写）

### 12.1 Android 优先（ADR-008）

v1.0 主张 iOS 先于 Android。v1.1 改为 Android 优先，理由：

- 国内用户以 Android 为主，第一批测试设备是 vivo。
- MediaStore 可以在用户授权后完整遍历相册并增量续扫，这是"一键导入、3 分钟看到地球"的前提；Web 文件选择做不到。
- WebView 壳复用同一套 Web 渲染与领域代码，没有推倒重写渲染器。

现状：Android 10+ WebView App、源受限的原生消息桥、MediaStore 权限 / 日期范围 / 分页、持久续扫、原生 HEIC 缩略图、JVM 单测、Lint、可复现的未签名 Release APK（[ANDROID_PHOTO_IMPORT.md](ANDROID_PHOTO_IMPORT.md)、[NATIVE_PLATFORM.md](NATIVE_PLATFORM.md)）。**真机未运行。**

### 12.2 各端分工

| 端 | 角色 | 不做 |
|---|---|---|
| Android App | 主力：相册导入、增量更新、日常使用 | 不桥接整个相册二进制，只传 ID 与必要缩略图 |
| Web Editor | 桌面整理与导出；手动选照片导入，流程与 App 一致 | 不承诺遍历整个相册 |
| Web Viewer | 零安装观看分享，独立源部署，不含个人 Repository 与导入模块 | 首屏不强制加载完整 3D |
| iOS | Beta 0.3 后评估（Capacitor / WKWebView + PhotoKit 先做可行性验证） | — |
| 原生渲染器 | 只有 WebGL 性能、媒体编码或用户分布证明 Web 长期不达标时才评估 | — |

必须区分三种媒体引用的生命周期：设备私有引用、`blob:` 会话 URL、云端媒体 URL。

### 12.3 发布与部署

开发阶段保持无构建依赖、`python3 serve.py` 本地运行；生产输出 `dist/editor`、`dist/viewer`、`dist/native`，Editor 与 Viewer 不同源。Web 与 Android CI 在 `main` 与 PR 上运行，Release APK 禁用缓存重跑后逐字节比较。正式签名、国内商店上架流程尚未建立（§13.3）。

## 13. 地图数据许可、地理服务与合规

### 13.1 当前依赖

CesiumJS（Apache-2.0）、NASA 历史影像、Esri World Imagery / World Elevation、Natural Earth v5.1.2（公有领域）、OurAirports（公有领域）、Nominatim / OpenStreetMap（仅经同意的单点查询）、自有程序化 GLB。仓库自身 MIT 许可不等于所有卫星图、瓦片与第三方数据都可商业再分发。

### 13.2 地名服务（ADR-009）

v1.0 的担忧是"百万级照片反查不能建立在公共 Nominatim 上"。现状已改为：**离线行政区与城市数据为默认**，照片坐标不发给任何第三方；在线查询只在用户对单个地点主动点击、确认后发送，并遵守约 1 次 / 秒的速率。

剩余尾巴：`app.js` 中旧的 CSV 地名校正流程仍直接调用 Nominatim（`app.js:364` 起），需要接到同一个经同意的适配器，或改为离线解析。

瓦片 URL、令牌、并发、条款与署名都视为部署配置，不绑定进安装包；`GeocodingProvider` / `TerrainProvider` / `BasemapProvider` 保持可替换。Esri 影像与地形在商业上线前必须逐项核对商业使用、流量、缓存与署名要求。

### 13.3 国内上架与合规（ADR-010，新增）

国内优先带来一组 v1.0 没有覆盖的硬约束。以下为风险清单与建议方向，具体以法务与主管部门要求为准。

**1. 国家与地区命名（阻断项）**

离线数据来自 Natural Earth 默认视角：台湾数据包的国家名为"中华民国"，香港、澳门作为独立国家条目，中印争议地区按 Natural Earth 的划分归属。面向国内发布时，这会导致商店审核不通过并带来法律风险。需要：

- 台湾作为中国的省级行政区显示；香港、澳门显示为特别行政区；统计口径统一为"国家 / 地区"，并在计数规则中明确港澳台不另计为国家。
- 争议地区的归属按国内标准处理。
- 修复后用"重新整理足迹"让已导入数据更新显示名，人工改名不受影响。

**2. 地图审核与底图**

向社会公开的地图通常需要审图号。可选方向：底图改用已有审图号的服务（例如天地图；它使用 CGCS2000，与 WGS84 的差异对本产品可以忽略，不需要 GCJ-02 偏移），并按国家标准地图处理国界；保留 Esri 作为境外版本或可配置项。要评估的：天地图的商业使用条件、全球覆盖与风格化处理是否允许、Esri 高分影像在国内公开展示的限制。

**3. 坐标系**

照片 EXIF 通常是 WGS84，但部分国产相机或第三方相机可能写入偏移坐标。需要用 vivo 等真机的真实样本核实；如果出现偏移，在 Evidence 中记录坐标系并在导入时转换，不能静默混用。若底图换成 GCJ-02 的商业服务（高德、腾讯），渲染侧需要统一转换。

**4. 个人信息保护**

行踪轨迹属于《个人信息保护法》中的敏感个人信息，处理需要单独同意，并说明目的与必要性。当前原图与坐标都在本机处理，这是最大的合规优势，必须保持。需要：首次启动在申请权限前展示隐私政策；"照片位置"权限单独说明；个人信息与第三方 SDK 清单；用户可导出、删除全部数据。分享托管与将来的同步一旦涉及服务器，数据应境内存储，避免跨境传输。

**5. 上架主体与渠道**

国内安卓商店（华为、小米、OPPO、vivo、应用宝等）通常要求 APP 备案、软件著作权、隐私合规检测与开发者实名，部分能力（微信登录、微信支付、支付宝）需要企业主体。这决定了 Public Beta 之前必须先确定运营主体（§23）。

**6. 分享与登录**

现有托管分享运行在境外（Sites 托管、Sign in with ChatGPT 登录、Cloudflare D1 / R2），国内用户无法顺利登录，分享页在国内网络的可达性与速度也没有保证。国内版需要境内托管（已备案域名 + 境内对象存储），登录改为手机号或微信；分享页要能在微信内置浏览器中打开（§16.4）。静态 ZIP 与 JSON 导出不受影响。

**7. AI（P3）**

面向公众提供生成式 AI 服务需要按国内规定备案或使用已备案的模型服务。在 P3 启动 AI Narrator 前评估。

## 14. 隐私、安全与威胁模型

### 14.1 高敏感数据产品

位置历史可推断住址、工作单位、作息、关系网络与出入境轨迹。即使不上传照片，精确地点与时间线也足以重新识别个人。隐私失误的代价远高于普通消费 App 的错误。

### 14.2 最小化与目的限制

- **本机默认**：EXIF / GPS 与原图在设备上处理；云端操作必须显式说明与授权。
- **敏感字段分离**：精确坐标与显示用城市名分开；旅程的私密时间与公开月份可以不同。
- **默认私密**：章节、旅程、记忆初始私密；分享前先展示对外实际可见的内容。
- **默认粗粒度**：对外发布城市级位置；住址、学校位置有额外提示。
- **元数据纪律**：导出的缩略图去除 EXIF；故事包只含用户选中的媒体。
- **用户控制**：按章节 / 旅程 / 照片撤回、归档、删除；区分本机删除与托管删除的不同行为；提供"删除全部本机数据与派生结果"（待补）。

### 14.3 威胁模型（简版 STRIDE）

| 威胁 | 后果 | 优先控制 | 现状 |
|---|---|---|---|
| 分享链接枚举 / 泄露 | 他人获知生活历史 | 不可预测凭据、最小分享投影、可撤销 | 256-bit 片段凭据走请求头，不进 URL 查询；可撤销 |
| 媒体 EXIF 泄漏 | 精确地址与时间公开 | 发布前清除元数据 | 隐私审查 + 照片审批 |
| 恶意文件导入 | ZIP 炸弹、畸形 EXIF、超大 GPX | 大小 / 深度限制、流式解析 | ZIP 安全输入已做；GPX 解析器上线时同步加限制 |
| 浏览器存储丢失 | 多年历史不可恢复 | 持久存储、设备外备份、恢复校验 | 统一备份已做；持久存储与提醒待做 |
| 分享资源跨站读取 | 未授权获取私有对象 | 服务端逐资源鉴权、CSP、Viewer 独立源 | 已做 |
| 第三方瓦片与地名查询 | 向第三方泄露位置请求 | 离线默认、可配置提供方、用户说明 | 地名离线默认；瓦片请求仍发往影像服务 |
| 同步冲突 | 历史被覆盖 | 版本日志、CAS、备份演练 | 仅设计 |

### 14.4 "本地优先"的如实披露

即使照片在本地处理，地图影像、真实高程仍需联网请求服务商；在线地名查询经用户确认才发送。用户需要看到四种数据流：**本机处理、第三方地图请求、用户主动发布、可选同步**，而不是一句"所有数据永不离开设备"。"我的 → 隐私说明"应按这四类说明。

# 第三部分｜AI、叙事、商业与落地

## 15. AI Layer（P3）

AI 不存储事实，也不是旅行攻略聊天框。它以 Life Graph 的结构化证据为上下文，把用户难以手工整理的空间记忆转成可核实的叙事草稿：检索 + 推理 + 受约束生成 + 校验。

| 功能 | 输入 | 输出 | 上线条件 |
|---|---|---|---|
| 阶段建议 | 居住、旅程、用户标题偏好 | 可编辑的章节建议 | 语义对象与纠错稳定 |
| 旅程回顾 | 已确认地点、照片标题、注记 | 短篇回顾草稿 | 来源可回溯 |
| 年度回顾 | 章节、旅程、统计 | 年度叙事与文案 | 时间口径可靠 |
| 自然语言查询 | Life Graph + 语义索引 | 带来源的结果 | 明确授权、限制敏感范围 |

流程：用户意图与授权 → 限定范围的 Life Graph 查询 → 带 claim ID 的上下文 → 带引用的草稿 → 确定性校验（日期、地名、实体引用）→ 编辑器高亮无依据段落 → 用户批准。任何外部模型请求都需要独立开关、字段级脱敏和"将发送哪些数据"的预览；拒绝云端 AI 不影响地球与章节功能。国内上线需满足生成式 AI 服务的备案要求（§13.3）。

Beta 0.3 的"年度回顾 / 阶段回顾"使用规则生成的统计与模板，不依赖 AI。

## 16. 分享产品与传播

### 16.1 分享是一次单独的数据发布

```
Share Projection = select(LifeGraph, 选区) → apply(隐私策略) → freeze(快照) → serialize(viewer 包)
```

一次分享只包含选中的章节、旅程、地点标签、可公开的媒体衍生件与镜头脚本，不捎带整个 Life Graph 或 Evidence。

### 16.2 现状

故事编排与隐私审查（展示实际 JSON、照片审批、勾选同意）、静态 ZIP、托管发布三种访问方式（私密：仅所有者；不公开链接：所有者或持 256-bit 凭据者；公开：匿名可读）、更新需重新审查、撤销与墓碑、独立 Viewer、一键分享面板（时段选择 + 单一按钮）。见 [HOSTED_SHARING.md](HOSTED_SHARING.md)、[LIFE_STORY.md](LIFE_STORY.md)。

### 16.3 三种形态

| 形态 | 优点 | 成本 / 风险 | 场景 |
|---|---|---|---|
| 互动网页 | 强交互、零安装、品牌差异 | 冷加载、GPU 兼容、托管 | 深度分享 |
| 短视频（15–30 s） | 易在短视频平台传播 | 编码 / GPU 成本 | 获客 |
| 海报 / 长图 | 生成快、易存档、微信友好 | 叙事深度有限 | 年度回顾、点亮成就 |

不预设互动网页一定胜出。分别追踪：创建率、实际发送率、打开成功率、观看 / 操作完成率、观看者转为自建率。

### 16.4 国内传播的调整

国内分享主要发生在微信（朋友圈、私聊、群）：

- **海报 / 长图优先级上调**：朋友圈只能直接发图片；中档机的微信内置浏览器打开完整 Cesium 3D 的成功率与速度未知。建议年度回顾与点亮成就先出海报，互动网页作为"点开看完整回放"的二级入口。
- 互动网页在微信内打开：境内托管 + 已备案域名，首屏先给静态封面或 2D 地图，再按设备档位升级到 3D。
- 观看者不需要登录；"创建你自己的地球"的引导不能遮挡作品本身。
- 不以公开精确位置作为免费使用的条件。

## 17. 商业模式

### 17.1 原则（不变）

基础导入、个人地球、人生阶段与基础回放免费，让用户先看到自己的世界——在此之前收费会破坏激活。高级场景、电影化制作、高质量导出适合一次性买断；同步、托管分享、AI、媒体存储这类持续成本的服务才订阅或按量计费。个人历史的基础访问与导出权不依赖持续付费。

### 17.2 定价假设（人民币，待实验）

| 层级 | 假设价格 | 权益 | 成本逻辑 |
|---|---|---|---|
| 免费 | ¥0 | 相册导入、个人地球、人生阶段、基础回放、手动编辑、开放导出 | 建立价值与信任 |
| 永久高级版 | ¥38 / ¥68 / ¥98 三档测试 | 高级场景与主题、高清海报 / 视频导出、创作工具 | 一次性本地权益 |
| Plus（P2 之后） | 年付约 ¥98–168 | 多设备同步、托管分享额度、有限 AI 用量 | 匹配持续成本 |
| 云端媒体（P3） | 单独计量 | 原图 / 视频长期托管 | 按存储与流量 |
| 机构（P3） | 按项目 | 空间叙事项目授权 | 销售与定制成本 |

这些价格是起点假设，没有经过国内竞品价格校准（§6.1 待补）。永久版不得承诺永久无限 AI 或无限云存储。停止 Plus 后保留本地数据与已购本地权益，托管内容按条款进入只读或限额状态。

国内收款需要企业主体与支付渠道（微信支付、支付宝、商店内购及其分成），这是付费实验的前置 Gate（§21.3 Gate D）。

### 17.3 收入敏感性（不是预测）

单位激活用户毛收入 = 购买率 × 售价。以 10,000 个已看到个人地球的用户为例，¥68 × 5% = ¥34,000，未扣除渠道分成、税费、退款与获客成本。只有计入这些成本后才能谈贡献毛利。

### 17.4 早期不做的收入模式

广告（需要规模且侵蚀隐私）、出售位置或画像（违背核心承诺）、旅游 OTA 导流（退回规划赛道）、重度 B2B 定制（挤占产品验证）。

## 18. 成本结构

边际成本主要来自：地图瓦片 / 地形、在线地名、托管存储与 CDN 流量、视频渲染、AI 推理、支付处理。本机渲染与本机索引不随用户量产生同等服务器成本；离线地名进一步消除了按照片数量计费的反查成本。

```
月度 COGS = 影像请求 × 单价 + 托管 GB·月 × 存储单价 + 出口流量 × 单价
          + 生成视频 × 渲染成本 + 模型 token × 单价 + 固定基础设施
```

单价按实际签约的境内供应商填写，不编造。应能计算：每激活用户成本、每次分享查看成本、每个 AI 故事成本。客户端只统计匿名聚合的影像请求量与导入规模，不为商业分析收集轨迹。

## 19. 指标体系与实验

### 19.1 定义

- **激活**：成功导入自己的一段历史，并在自己的地球上打开至少一个旅程或人生阶段；示例数据不计入。
- **D7 留存**：以激活当天为第 0 天，第 7 天有有效返回。
- **有意义的返回**：查看、修正、补充或分享自己的真实历史；后台增量导入不计入。
- **阶段完成**：至少两个有有效时间范围的阶段被起名或确认。
- **可信质量**：修正率、误推断反馈、恢复成功率、分享隐私事故数。

### 19.2 分阶段的判断方式

**Beta 0.3（5–10 位真实用户）只能做定性验证。** 记录导入完成率、轻确认跳过率、修正次数、阶段起名率、首次分享率（本地记录，用户同意后导出匿名汇总，见 BETA_0_3）。这个样本量不能得出统计结论，只用来发现阻断问题与验证情绪时刻。

**Public Beta 之后**才使用以下门槛（内部假设）：

| 指标 | 目标假设 | 用途 |
|---|---|---|
| 导入 → 个人地球成功 | ≥ 65% | 首入可用性 |
| 首个城市出现 | ≤ 60 s | 首次感知价值 |
| 推断到访 / 旅程精度 | ≥ 90%（人工标注集） | 可信度 |
| D7（激活用户） | ≥ 20% | 复访价值 |
| W1 有意义返回 | ≥ 30% | 持续使用 |
| 激活 → 分享 | ≥ 8% | 作品价值 |
| 激活 → 购买 | 3–5%（早期信号） | 付费意愿 |
| 升级 / 重开数据完整性 | ≥ 99.9% 且有恢复通路 | 长期信任 |

样本量参考（双侧 α = 0.05、power = 0.8 的独立二项检验近似）：购买率 3% → 5% 约 1,484 人 / 组；分享率 8% → 12% 约 875 人 / 组；D7 15% → 20% 约 902 人 / 组。

### 19.3 实验

- **E1 首入**：v1.0 计划对比"先看示例地球"与"先导入照片"。v1.1 已按产品判断选定"先导入照片 + 渐进点亮"；Public Beta 后若激活不达标再回到对比实验。
- **E2 人生阶段的增量价值**：对照组只有旅程时间轴，实验组加可命名、可重叠的阶段。看 D7、30 天阶段保留、补充记忆、分享与付费倾向。如果实验组只是"好看"而没有复访或分享收益，需要重新审视核心假设。
- **E3 分享形态**：海报 vs 20 秒短视频 vs 互动网页，按 §16.3 拆分指标。国内微信环境下不预设结论。

### 19.4 数据质量仪表

每周查看：带 GPS 照片占比分布；导入失败按格式 / 权限分类；无效坐标比例；旅程拆分 / 合并率；人工覆盖推断率；日期精度分布；章节关联错误；导入幂等性；备份 / 恢复失败；地图服务超限；移动端帧率与 P95 帧间隔。

## 22. 风险与架构决策

### 22.1 风险矩阵

| 风险 | 可能性 | 影响 | 缓释 |
|---|---|---|---|
| 品牌与已有「Once Here（曾在）」相近 | 高（已存在） | 高 | 上架前商标与商店检索，准备备选名 |
| 国内命名 / 地图合规不过审 | 高（已发现阻断项） | 极高 | 修正国家 / 地区命名；审图方案；Gate C 前法务确认 |
| 零真机证据，桌面结论不成立 | 高 | 极高 | ROADMAP 真机轨道；未测即写未测 |
| 自动整理让推断冒充事实 | 中高 | 高 | 来源标识、可撤销、重新整理保护人工修改（ADR-007） |
| WebView 存储丢失长期数据 | 中 | 极高 | 持久存储、备份提醒、跨设备恢复校验 |
| 分享暴露生活隐私 | 中 | 高 | 分享投影、字段白名单、预览、撤销、默认城市级 |
| 移动端 3D 耗电 / 崩溃 | 中高 | 高 | 画质分级、弱机降级、海报优先 |
| 美术投入挤占产品验证 | 高 | 中 | 渲染以帧率与回归为主，限额精修 |
| `app.js` 耦合拖慢时间机器开发 | 中高 | 中 | I3 先拆分再做 I4 |
| 人生阶段只被当成年份标签 | 中 | 高 | 草稿 + 起名 + 阶段回放 + E2 实验 |
| 地图与地名服务商业授权不符 | 中 | 高 | 提供方抽象、离线地名、境内底图评估 |
| 个人维护者过载 | 高 | 高 | 先 Android + Web，iOS 与云延后 |

### 22.2 ADR 摘要

- **ADR-001 保留单 Cesium 引擎。** 已有大量地理与渲染资产；代价是持续维护 Cesium 内部性能兼容。（不变）
- **ADR-002 先建 Canonical Life Graph。** 多源历史与人生语义必须共享来源；代价是早期需要迁移与 schema 测试。（不变）
- **ADR-003 本地优先，服务显式开启。** 长期敏感数据与信任；代价是跨端初期不如全云方便。（不变）
- **ADR-004 可解释推断。** 用户对"未知"的容忍高于对"伪造"的容忍；代价是自动化率可能低于激进竞品。（不变）
- **ADR-005 免费核心 + 永久本地高级版。** 低频、长寿命的个人数据更适合买断；订阅只用于持续服务；仍待实验。（不变，价格改为人民币假设）
- **ADR-006 分享投影而非整账户分享。** 隐私与更快的 Viewer；代价是独立的故事 schema 与发布系统。（不变）
- **ADR-007 自动整理优先，事后就地纠错（新增，2026-10-27）。** 背景：逐条审核让首次使用变长、需要理解系统概念，与"3 分钟看到自己的地球"冲突。决定：导入后自动保存城市、居住、旅程；最多问 3 个问题；其余错误在统一卡片里就地修正。约束：每个自动结果显示观测 / 推断 / 人工来源；所有修改可撤销；重新整理不覆盖人工修改；高级逐条审核保留在"高级"入口。代价：错误会先被用户看到，可信度依赖来源标识与纠错体验；需要用 Beta 的修正率与跳过率检验。
- **ADR-008 Android 优先（新增，替代 v1.0 的 iOS 优先）。** 背景：国内用户以 Android 为主；MediaStore 支持授权后的完整相册遍历与增量续扫；WebView 壳复用全部 Web 代码。决定：Android App 为主力，Web 为观看与桌面编辑，iOS 在 Beta 0.3 后评估。代价：iOS 用户的首次导入暂时只能走 Web 文件选择。
- **ADR-009 离线地名默认（新增）。** 背景：批量反查不能依赖公共 Nominatim，且照片坐标外发违背本地优先。决定：内置 Natural Earth 行政区、城市索引与大型机场数据离线解析；在线查询仅单点、经同意。代价：安装包增大，地名精度受限于离线数据，命名口径须自行维护（见 §13.3 第 1 条）。
- **ADR-010 国内优先（新增，2026-10-28）。** 背景：第一批用户、测试设备与传播渠道都在国内。决定：先满足国内上架与传播；国际版作为后续选项。影响：国家 / 地区命名、底图与审图、个人信息合规、境内托管与登录、人民币定价与国内支付、微信分享形态。代价：现有境外托管分享需要境内替代；海外竞品研究需要补充国内部分。

## 23. 开放问题与决策 Gate

1. **品牌**：OnceHere 与中文名的商标、商店、域名可用性未确认，需要备选名。（Gate D）
2. **运营主体**：个人还是企业？决定能否接入微信登录 / 支付、能否在各商店上架、APP 备案主体。（Gate C 前）
3. **底图与审图**：国内版用天地图、商业地图服务，还是保持风格化地球但不展示国界？Esri 影像在国内版是否保留？需要法务与提供方条款确认。
4. **国内分享托管**：境内对象存储 + 备案域名的选型；登录用手机号还是微信；现有境外托管是否保留为国际版。
5. **坐标系实测**：vivo 等国产机型自带相机与常用第三方相机写入的 EXIF 坐标系，需要真机样本核实。
6. **国内竞品与定价**：补一轮国内足迹 / 点亮类 App 的研究，校准 §17.2 的价格假设。
7. **人生阶段的价值**：用户会主动给两段以上阶段起名吗？这决定产品能否突破"旅行足迹"的心智。（Beta 0.3 定性、E2 定量）
8. **3D 的价值**：与海报 / 2D 相比，3D 是否提高复访或分享？在微信环境下尤其需要实验。
9. **WebView 存储可靠性**：真机上卸载、清数据、覆盖安装后的行为，决定是否需要原生 SQLite（§10.2）。
10. **分享默认粒度**：默认只公开城市级、月粒度？建议默认最保守，用可理解的界面允许放宽。

## 24. 战略总结

OnceHere 的差异化不是"地球上能放更多树"，也不是"每张照片都能贴到 3D 地球上"——这些会迅速商品化。长期价值来自四项组合：

**一份可信且用户拥有的个人时空历史 → 一组能表达重叠人生阶段的语义对象 → 一个从地球到地点连续叙事的 Living World → 一种由用户选择性公开的人生作品。**

短期目标是让第一次有位置历史的人不学 CSV 就得到自己的地球；中期证明用户愿意回来为人生阶段补上名字、故事与照片；长期才投资同步、AI Narrator、家庭共同记忆与机构空间叙事。

> Other products show where you've been. OnceHere lets you revisit who you were, where you were, and the stories that made you.

示例省略了部分必填字段（如到访的原始 CSV 行、各实体的 `evidenceIds`），完整校验规则见 `validateDataset`。

## 附录 B｜匿名事件协议

默认只在本地记录，用户同意后导出汇总，不自动上报。

| 事件 | 最小内容 | 禁止发送 |
|---|---|---|
| `import_started` | 来源类型、数量区间 | 图片字节、精确坐标 |
| `import_stage_finished` | 阶段、耗时区间、状态 | 地名明文、文件名 |
| `first_city_shown` | 耗时区间、设备档位 | GPS、拍摄时间 |
| `first_use_answered` | 问题序号、选择（对 / 改 / 跳过） | 城市名、日期 |
| `correction_applied` | 字段类别、修正类型 | 修正前后的值 |
| `chapter_named` | 章节类型、时长区间 | 章节标题 |
| `story_shared` | 形态、隐私预设、状态 | 分享凭据、私人内容 |
| `viewer_loaded` | 设备档位、加载时间、阶段 | 作者的 Life Graph |
| `backup_restored` | schema 版本、状态 | 备份内容 |

"匿名"不自动等于真正匿名：会话标识与细粒度事件组合仍可能重新识别，必须做数据最小化与保留期限控制，并符合个人信息保护要求。
