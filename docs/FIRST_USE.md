# 首次导入、轻确认与人生阶段草稿

2026-10-28。Android 系统相册和 Web 文件选择默认使用自动整理，旧逐条审核保留在“高级导入与记录”。本轮不代表完整 Beta 0.3 或真机验收完成。

## 用户路径

1. 从相册开始；Android 申请相册和照片位置权限，Web 主动选择原图、文件夹或压缩包。
2. 自动读取已有照片的时间、坐标和离线地名，保存城市 / 居住 / 旅程及照片关联。Web 不再要求逐条审核候选或填写日期，保留可解码的小预览图；无地点照片保留记录但不编造城市或旅行。原图不上传、不复制。
3. 点击“去地球上看看”揭晓城市、旅程及国家 / 地区数量。正常动态偏好下短暂展示后自动开始首次足迹回放；最多四个代表地点，包含镜头移动的播放时间上限约 20 秒。可关闭或暂停，后台会暂停。减少动态效果时不自动播放，保留手动回放入口。
4. 最多三个轻确认：先问现居，再问拍照日最少的曾居判断。每问显示照片数和拍照日依据；“对”“改一下”“跳过这项”，或者直接“先看地球”。改判可选现居、曾居、旅行、路过、转机。没有日期文本输入。
5. 已推断的居住时段生成“某城的日子”阶段草稿；未问或跳过的保持“推断”。确认 / 改判进入人工来源与撤销历史。多段居住引导阶段起名；以旅行为主引导年度分享。起名直接打开统一卡片，已生成的时间范围不要求重新填写。

## 存储与一致性

`meta.firstUse` 保存有上限的问答队列、已回答项、阶段 ID 和完成标志；备份 / 重载后继续未完成流程。回答被撤销后恢复实体来源和原 ID，但不重置已经送达的问题额度。确认的 Residence 和 Stage 使用现有可撤销命令写入，只有写后读回成功才推进。跳过不附加人工证据。会话撤销能力沿用编辑历史；跨会话保留确认结果及审计，而非整份撤销栈。

阶段 `draft` 保存来源居住 ID 和推断 / 确认状态。确认的居住不再被自动整理覆盖；阶段改名保留原 ID、标题与照片关联。把现居改判成旅行时，结束时间使用末次照片观测（无照片则未知），避免把“持续至今”误用为一段长期旅行。照片观测范围不等同于已经证实的搬家或到达 / 返程日期。

Web 自动导入保留 `media:` 指针和媒体索引，Android 保留原 `android-media:` 指针；两者共享城市分组规则。自动 Web 记录不会被当成旧审核导入删除。批次先保存准备标记，Canonical 保存后再确认媒体索引，失败可通过原图重选 / 恢复检查重试。小预览图失败不丢弃照片记录。默认去重保持照片、城市和旅程 ID；已完成轻确认不会在增量导入或重新整理后重新弹出。清空个人数据同时清空首次使用进度。

## 证据与边界

- `first-use.test.mjs`：三问上限与顺序、推断来源、确认 / 改判 / 撤销、备份重载、跳过、重整保护、保存失败、避免持续中的旅行。进度保存失败后的重试只撤销本流程实际创建的命令，不会误撤销之前的其他编辑。
- `web-auto-import.test.mjs`：无需审核的自动提交、无地点指针、去重不重写、重整 ID、写入失败恢复、取消后续扫。
- `first-use-browser.mjs`：127 张有效 JPEG / EXIF 合成夹具（五段居住、一段旅行、一张无 GPS），验证 Web 无逐条审核、三问中重载、改判 / 跳过 / 撤销、阶段起名、重整、重复导入、首次自动回放及暂停恢复。
- 既有 Android 模拟端口和高级照片导入回归继续运行。所有浏览器结果都是桌面自动化，不是 Android 真机、真实相册或真实用户结果。

仍待：扫描中渐进点亮、真机首城与全量导入耗时、两设备恢复、持久存储请求与备份提示、“我的”入口、人生 / 年份时间轴切换、真实用户试用与本地指标。未发布 `v0.3.0`。
