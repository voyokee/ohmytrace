# OnceHere 可撤销编辑命令

2026-10-27，Beta 0.3 I1 的领域层基础。统一卡片的交互接入仍在后续工作中，本文不代表整轮可信纠错已验收。

## 行为

私人编辑器与 Android 的 `createLifeBridge()` 提供 `edits`。所有命令使用同一个 Repository 写入队列、版本校验和写后读回校验；成功保存后才进入撤销历史。示例和只读分享页不能保存修正。

当前命令：

- `rename`：城市、旅程、常驻、阶段改名；同步对应的派生地点名、旅程名和照片默认标题。
- `classify`：城市、常驻、旅程的旅行 / 路过 / 转机 / 现居 / 曾居分类，以及阶段类型。多城市旅程不能整体改成一处居住，需到具体城市确认。
- `merge`：城市、旅程或阶段合并。第一条记录保留 ID；所有到访、常驻、阶段、照片关系重定向并去重。
- `split`：选择旅程的部分地点拆成另一段；原旅程保留 ID，新旅程分配新 ID，照片和阶段关联随之拆分。单地点旅程按照片日期拆分还需后续命令。

每次修正给受影响实体附加人工来源，修订中记录本次实际变化的字段。原始照片观测留存。操作来源、命令 ID 和执行 / 撤销 / 重做的审计记录进入备份；会话撤销栈默认最多 30 条，并按序列化大小估算使用 8 MiB 预算；超过预算时先释放更早的命令，始终保留最新修改的撤销。历史不持久保存全部数据集副本，8 MiB 是估算预算而非 JavaScript 实际堆内存上限。

`undo()` / `redo()` 仅恢复受影响实体及其原 ID，保留之后新增的无关记录。若受影响实体已被别的操作修改，或恢复到了另一个数据集，就明确拒绝覆盖。保存失败不改变撤销栈；写后读回失败沿用 Repository 的不确定状态保护。

## 与自动整理的关系

- 离线名称刷新跳过有人工来源的城市，异步查询在提交时再检查一次，避免旧查询覆盖新修正。
- 城市合并保存原行政城市键。重新整理即使遇到相距超过自动复用半径的原城市，也保留用户选择的合并目标。
- 人工修改的旅程、常驻和照片归属继续受自动整理保护。命令的多实体修订按实体 ID 区分，不能把其他实体的类型变化误用为本城市的分类依据。
- `sourceSummary()` 分别返回人工、照片观测、记录观测、推断、来源待确认，不制造置信度百分比。

这些是可选的 schema v1 扩展字段（`visitType`、`mergedCityKeys`），有枚举、去重和字符串校验。既有 v1 数据无需迁移；不改动安装包标识、数据库名或已发布的分享格式。

## 验证与剩余工作

`node --test tests/life/edits.test.mjs tests/life/bridge.test.mjs` 覆盖 ID / 关系保留、撤销重做、失败原子性、队列、历史上限、只读保护、数据集恢复冲突、跨城市合并、重新整理、离线命名竞态和读回失败。

还需将这些命令接入统一卡片的“不对？”，补上单城市旅程的按照片拆分、删除后自动整理的排除规则，以及路过 / 转机在统计和回放中的统一处理。当前领域能力不能单独满足 Beta 0.3 的完整退出标准。
