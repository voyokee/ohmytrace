# OnceHere 迭代路线（2026-10-27 起）

基线：`feat/photo-first-onboarding` @ `cac3e97`。本文对照《OnceHere 产品与技术总目标》与 [白皮书](whitepaper.md) 盘点现状，确定下一阶段目标与迭代顺序。现状判断来自仓库代码与 `docs/` 下各阶段验收记录，不等于真机验收。

## 1. 现状盘点

| 总目标能力 | 已有 | 缺口 | 判定 |
|---|---|---|---|
| 数据层 | IndexedDB Canonical schema v1、校验事务、Legacy 迁移、Life Atlas JSON / 统一备份 | 无 GPX/GeoJSON/KML 导入导出；两库（Canonical/媒体）非原子；未请求持久存储；schema v2 迁移只有接口 | P0 大部分完成 |
| 足迹重建 | 网页 EXIF（JPEG/HEIC/PNG/WebP）、ZIP/目录、万张规模；Android 一键导入、离线行政区命名、按城市归并、常驻推断、72h 旅程切分、重新整理 | 一键导入跳过审核；无 转机/路过 类型；无 Route Segment 实体；Day/Place 级停留未建模 | 能力在，可信性待补 |
| Truth Model | Evidence 区分 observed/inferred/manual/unknown，修订记录，推测连接虚线 | 自动结果在 UI 上缺少来源/置信度标识；无可撤销编辑命令（undo/redo）；合并/拆分只覆盖部分实体 | P0 未收口 |
| Life Chapter | CRUD、城市锚点、关联旅行与记忆、可重叠 | 不支持嵌套（无 parent）；无 Chapter 级回放入口优化 | P1 起步 |
| 时间轴 | 全部/年份筛选、年/月聚合、旅行回放、调速播放器 | 五级视图只有 Overview/Year/Trip；Chapter 与 Day/Place 层缺失；地球→时间轴反向联动弱 | P1 主要工作 |
| Life Story / 分享 | 故事编排、隐私审查、静态 ZIP、托管分享（D1/R2）、可撤销链接、独立 Viewer、一键分享面板 | 短视频/海报导出；人类 SSO 与真机未验收 | P1 基本完成 |
| 3D 世界 | 微缩地形、七类 GLB 植被、季节、GPU Instancing、LOD、Worker、自适应画质 | 高山/区域场景未持续 60 FPS；瓦片冷加载卡顿（曾测到 738 ms 帧）；无真机帧率；区域层默认关闭 | 持续打磨 |
| 架构 | `renderer-adapter.js` 投影、`src/life` 领域模块独立 | `app.js` 1843 行仍持有 UI/数据/飞行调度；无正式 SceneSlice（视角+时间裁剪） | 技术债 |
| 平台 | Android 10+ WebView App、MediaStore 增量、原生 HEIC 缩略图 | 未在真机运行（ADB 无设备）；无 iOS；WebView IndexedDB 持久性未验证 | P2 起步 |
| 云 / AI | 同步与原生边界仅有契约（`contracts.d.ts`、`CLOUD_SYNC.md`） | 未实现 | P3，暂不做 |

## 2. 当前最大风险

1. **最新导入能力尚未合入主干。** 2026-10-27 获取远端后，`origin/main` 为 `f7f1330`（PR #2，已合入 Life Atlas 基线）；`feat/photo-first-onboarding` 为 `cac3e97`，尚有 18 个提交待通过 PR 合入。`beta/0.3-foundation` 从该最新分支开发。现有发布标签为空；旧 CI 的 push 触发器仍指向 `feat/life-atlas-mvp`，本轮改为 `main` + PR。实时验收进度见 [BETA_0_3.md](BETA_0_3.md)。
2. **零真机证据。** Android 导入吞吐、vivo ROM 的 HEIC EXIF、1k/10k 真实相册、WebView 中的地球帧率与 IndexedDB 持久性都未测。产品体验目前只在桌面 Chrome 与模拟端口里成立。
3. **一键导入与 Truth Model 的张力。** 为降低门槛去掉了审核，常驻地、旅程都是推断；如果用户看不出哪些是推断、改了又不能撤销，"真实可信"就落空。
4. **`app.js` 耦合。** 时间机器的五级联动会大量改动时间轴与相机调度，在单体文件里继续堆叠，回归风险随每次迭代上升。
5. **开放导出缺失。** 目前只有自有 JSON 与 CSV，"不因退出失去数据"的承诺缺少 GPX/GeoJSON 这类通用出口。

## 3. 下一阶段目标：Beta 0.3「可信闭环上真机」

> 一位 Android 用户安装 OnceHere 后，一键导入真实相册，3 分钟内看到自己的地球；回答最多 3 个问题就得到人生阶段草稿；在任何城市/旅程/阶段的卡片上发现错误能就地改、能撤销；能完整备份、用开放格式导出；能按人生或年份回放并分享。全部在真机上验证。

用户侧的定位、首次使用流程与操作逻辑见 [PRODUCT.md](PRODUCT.md)。主平台 Android，Web 为观看与桌面编辑端；第一批用户为多城生活的年轻人与旅行爱好者。暂不进入 iOS、云同步、AI。

### 退出标准（全部可度量）

- **主干**：所有工作经 PR 合入 `main`，CI 在 `main` 与 PR 上全绿，打 `v0.3.0` 标签，Web 与 APK 可复现构建。
- **真机**：至少 2 台 Android（含 vivo，含一台中档机）完成导入 1k 与 5k+ 张真实相册：首个城市出现在地球上 ≤ 60 s，全量导入无崩溃；全球视角中档机中位数 ≥ 30 FPS，记录 P95 帧间隔；切后台/恢复、杀进程后续扫正确。
- **命名**：界面、App、分享页统一为 OnceHere，用户可见处不再出现旧名与 Memory/Evidence/JSON 等系统词。
- **首次使用**：导入后轻确认不超过 3 个问题，确认结果生成人生阶段草稿；全程无须填写日期格式。
- **可信**：每个自动生成的城市、常驻、旅程都显示来源（照片观测 / 推断 / 人工）；在统一卡片的"不对？"里完成改名、改类型（含路过/转机）、合并、拆分，均可撤销；"重新整理足迹"后人工修改不丢失。
- **数据主权**：完整备份在另一台设备恢复后实体与 ID 零差异；GPX/GeoJSON 导出能被常见工具读取；首次导入后应用请求持久存储并提示备份。
- **人生回放**：时间轴支持人生（阶段色带 + 旅程点）与年份两种模式，与地球双向联动；阶段、年份、旅程都能一键回放和分享。
- **Beta 用户**：两类用户合计 5–10 位真实试用，记录导入完成率、轻确认跳过率、修正次数、阶段起名率、首次分享率（本地、可选上报）。

## 4. 迭代计划（每轮 2 周，I0 为 1 周）

### I0｜收口与真机基线（10-28 → 11-03）

- 从 `feat/photo-first-onboarding` 开 PR 合入 `main`（体量大，按模块写清 PR 描述与已知限制）；CI 触发器改为 `main` + PR，并加入 Android JVM 单测与 Lint。
- `.DS_Store` 加入 `.gitignore`；打 `v0.2.0` 标签作为第一次可回溯的基线。
- 用户可见名称统一为 OnceHere（页面标题、App 名、分享页）。
- 建真机测试矩阵（机型/系统/相册规模/照片格式），在 vivo 上跑 `connectedDebugAndroidTest`，实测 EXIF 吞吐、HEIC、权限拒绝/限制访问、WebView 帧率与 IndexedDB 持久性，结果写入 `ANDROID_PHOTO_IMPORT.md`。
- 只修阻断性问题；其余问题进入 I1+ 的待办。

### I1｜统一卡片与就地纠错（11-04 → 11-17）

- 领域层新增可撤销编辑命令：每次修改生成命令记录并写入 Evidence 修订，支持 undo/redo 与会话内历史。
- 城市、旅程、阶段共用一种底部卡片，固定"回放 · 照片 · 分享 · 不对？"四个动作，替代"地点校正"等独立弹窗。
- 卡片显示 观测 / 推断 / 人工 与依据（例如"按 2023 年 41 个拍照日推断为常驻"）。
- "不对？"内完成改名、改类型（新增 **路过 / 转机**，不计入旅行）、合并/拆分旅程、常驻改判；改后出现"已修改 · 撤销"。

### I1.5｜轻确认与阶段草稿（并入 I2 前半周）

- 导入完成后最多 3 个问题：现居/曾居判断与置信度最低的项；可跳过。
- 确认的居住时段自动生成人生阶段草稿（城市 + 起止），用户只需起名；替代手填日期表单。
- 网页导入改用同一轻确认流程，取消逐项审核。

### I2｜数据主权与"我的"（11-18 → 12-01）

- 工具栏收为"分享 · 添加照片 · 我的"；备份恢复、导入导出、夜景、隐私说明集中到"我的"，CSV/GPX/JSON 归入"高级"。

- GPX / GeoJSON 导入（旅行轨迹作为 observed Route Segment）与导出（地点、旅程、可选轨迹）；KML 视需求跟进。
- 新增 Route Segment 实体：区分实测轨迹与推测连接，渲染层按来源用实线/虚线。
- schema v2 迁移落地（Route Segment、Chapter `parentId`），带迁移前自动备份与回滚测试。
- `navigator.storage.persist()`、备份提醒；Android 端验证卸载/清数据/覆盖安装的数据行为并写入文档。
- 统一备份覆盖 Android 媒体指针，跨设备恢复时明确标记"原图不在本机"。

### I3｜SceneSlice 与 app.js 拆分（12-02 → 12-15）

- 定义 `SceneSlice(viewport, timeRange, scope)`：由 Life Graph 生成、渲染器只读消费；地点标记、路线、点亮、回放全部改走 SceneSlice。
- 从 `app.js` 拆出时间轴、旅行卡片、飞行调度、数据入口模块；每拆一块先补浏览器回归测试再移动代码。
- 不改渲染画面；以现有截图/帧率测试为回归护栏。

### I4｜人生回放 v1（12-16 → 2027-01-05，含假期缓冲）

- 时间轴两种模式：**人生**（居住阶段色带 + 旅程点，色带可起名）与 **年份**（保留现有筛选和年/月聚合）；阶段可重叠显示。
- 双向联动：时间轴选择驱动相机与 SceneSlice；地球上点城市/旅程反向定位时间轴与卡片。
- 统一播放器：阶段、年份、旅程都能播放、暂停、跳转、调速；阶段回放串联常驻城市、旅程与照片。
- 年度回顾与阶段回顾作为分享主入口，复用现有 Story 与分享面板。

### I5｜首次使用与性能（2027-01-06 → 01-19）

- 按 [PRODUCT.md](PRODUCT.md) 首次使用流程：扫描中城市逐个点亮 → 数字揭晓 → 自动约 20 秒回放 → 轻确认 → 按用户类型引导起名或年度回顾；量化"首次看到地球"时间。
- 持续使用：打开即增量导入并提示新旅程；居住地变化时提示给上一段起名。
- 定位并缓解瓦片冷加载卡顿；高山场景在中档机上的降级档位。
- 本地性能与崩溃记录（冷启动、帧间隔、内存），用户可选择上报。
- Beta 用户招募与反馈收集，按第 3 节退出标准做 0.3 验收，写验收记录。

## 5. Beta 0.3 之后

按 Beta 数据决定优先级，候选方向：

- **P2 产品化**：iOS（Capacitor + PhotoKit，先做可行性验证）、分享海报/短视频导出、可访问性、留存与分享漏斗、一次性解锁的付费实验。
- **P1 深化**：Day/Place 完整视图、记忆（文字/语音）与照片的关联编辑、电影化回放镜头。
- **3D 世界**：区域层默认开启、枝叶精细度、全球→近景衔接收尾。
- **P3**：仅在 Beta 证明有跨设备需求后启动快照同步（按 `CLOUD_SYNC.md` 的 CAS/三方合并设计）；AI Life Narrator 在 Life Graph 与 Evidence 稳定后再接入。

## 6. 工作约定

- 每轮结束：合入 `main`、打标签、更新对应 `docs/` 验收记录；真机未测的项写明"未测"，不以模拟结果代替。
- 每项功能先补测试，再改实现；渲染相关改动必须附前后帧率记录。
- 新的用户可见推断都要带 Evidence 与来源标识，新编辑操作都要可撤销。
