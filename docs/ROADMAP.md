# OnceHere 迭代路线（2026-10-27 起，10-28 重排）

基线：`main` @ `04ee028`（PR #1–#7 已合入，`v0.2.0` 指向 `afc902d`）。本文对照 [白皮书 v1.1](whitepaper.md)（已并入原《OnceHere 产品与技术总目标》）盘点现状，确定下一阶段目标与迭代顺序。现状判断来自仓库代码与 `docs/` 下各阶段验收记录，不等于真机验收；逐项证据见 [BETA_0_3.md](BETA_0_3.md)。

## 2. 当前最大风险

1. **国内口径的国家 / 地区命名是阻断项。** 离线数据 `src/life/geocoding/data/TWN.json` 的国家名为"中华民国"，港澳作为独立国家条目参与"几个国家"统计（`first-use.js` 按 `country` 计数），争议地区按 Natural Earth 划分。Beta 0.3 的测试用户在国内，揭晓页第一屏就会出现这些数字和名称，因此放进本阶段第一项（I2），而不是等到上架前。
2. **零真机证据。** Android 导入吞吐、vivo ROM 的 HEIC EXIF、1k/10k 真实相册、WebView 中的地球帧率与 IndexedDB 持久性都未测。产品体验目前只在桌面 Chrome 与模拟端口里成立。没有设备时，这一项无法由工程推进（§4 真机轨道）。
3. **分享在国内不可用。** 托管分享依赖 Sites + Sign in with ChatGPT + Cloudflare D1/R2。Beta 0.3 用静态 ZIP、图片和本地预览兜底；境内托管放到 Public Beta 前（§5）。
4. **`app.js` 耦合。** 人生时间轴与地球双向联动会大量改动时间轴与相机调度，在单体文件里继续堆叠，回归风险随每次迭代上升。
5. **开放导出缺失。** 目前只有自有 JSON 与 CSV，"不因退出失去数据"的承诺缺少 GPX/GeoJSON 这类通用出口。

原风险"最新导入能力未合入主干"已解除（PR #3–#7）；"一键导入与 Truth Model 的张力"已由统一卡片、来源标识和撤销缓解，剩余部分是真机验证。

## 3. 下一阶段目标：Beta 0.3「可信闭环上真机」

> 一位 Android 用户安装 OnceHere 后，一键导入真实相册，3 分钟内看到自己的地球；回答最多 3 个问题就得到人生阶段草稿；在任何城市/旅程/阶段的卡片上发现错误能就地改、能撤销；能完整备份、用开放格式导出；能按人生或年份回放并分享。全部在真机上验证。

用户侧的定位、首次使用流程与操作逻辑见 [PRODUCT.md](PRODUCT.md)。主平台 Android，Web 为观看与桌面编辑端；第一批用户为国内多城生活的年轻人与旅行爱好者。暂不进入 iOS、云同步、AI。

### 退出标准（全部可度量）

- **主干**：所有工作经 PR 合入 `main`，CI 在 `main` 与 PR 上全绿，打 `v0.3.0` 标签，Web 与 APK 可复现构建。
- **真机**：至少 2 台 Android（含 vivo，含一台中档机）完成导入 1k 与 5k+ 张真实相册：首个城市出现在地球上 ≤ 60 s，全量导入无崩溃；全球视角中档机中位数 ≥ 30 FPS，记录 P95 帧间隔；切后台/恢复、杀进程后续扫正确。
- **命名**：界面、App、分享页统一为 OnceHere，用户可见处不再出现旧名与 Memory/Evidence/JSON 等系统词。
- **国家 / 地区口径**：台湾显示为中国台湾（省级），香港、澳门显示为中国香港、中国澳门特别行政区；港澳台不另计为国家，统计文案为"国家 / 地区"；已导入数据经"重新整理"更新显示名，人工改名不受影响；有回归用例覆盖。
- **首次使用**：申请相册与位置权限前展示隐私说明（原图不上传、位置用于什么）；导入后轻确认不超过 3 个问题，确认结果生成人生阶段草稿；全程无须填写日期格式。
- **可信**：每个自动生成的城市、常驻、旅程都显示来源（照片观测 / 推断 / 人工）；在统一卡片的"不对？"里完成改名、改类型（含路过/转机）、合并、拆分，均可撤销；"重新整理足迹"后人工修改不丢失。
- **数据主权**：完整备份在另一台设备恢复后实体与 ID 零差异；GPX/GeoJSON 导出能被常见工具读取；首次导入后应用请求持久存储并提示备份；地名解析默认不发出任何网络请求。
- **人生回放**：时间轴支持人生（阶段色带 + 旅程点）与年份两种模式，与地球双向联动；阶段、年份、旅程都能一键回放和分享。
- **Beta 用户**：两类用户合计 5–10 位真实试用，记录导入完成率、轻确认跳过率、修正次数、阶段起名率、首次分享率（本地、可选上报）。

## 4. 迭代计划（每轮 2 周）

### 已完成（2026-10-27 → 10-28）

- **I0 收口**：PR #3 合入、`v0.2.0` 标签、CI 改为 `main` + PR 并加入 Android JVM 单测 / Lint / 可复现 Release、名称统一为 OnceHere。真机测试矩阵已建表，但无设备未执行，转入真机轨道。
- **I1 统一卡片与就地纠错**：可撤销编辑命令（PR #4）、深港归属与路过 / 转机推断（PR #5）、四类统一卡片与分享范围（PR #6）。
- **I1.5 轻确认与阶段草稿**：最多三问、阶段草稿、网页同流程（PR #7）。

### I2｜国内口径与数据主权（10-29 → 11-11）

- **国家 / 地区命名修正**（先做）：离线数据增加国内口径的显示名与归属映射（台湾、香港、澳门、争议地区），不直接改写 Natural Earth 原始几何；"几个国家"统计按新口径计数；城市索引与在线适配器的输出走同一映射；地名包缓存 ID 升级，触发已安装设备重新整理；补领域与浏览器回归用例。
- 移除 `app.js` 旧 CSV 地名校正流程对 Nominatim 的直接调用，改走 `provider.js`（默认离线，在线仅单点、经同意）。
- 工具栏收为"分享 · 添加照片 · 我的"；备份恢复、导入导出、夜景、隐私说明集中到"我的"，CSV/GPX/JSON 归入"高级"。
- GPX / GeoJSON 导出（地点、旅程、阶段）；用常见工具验证可读。
- `navigator.storage.persist()`、首次导入后的备份提醒；Android 端验证卸载/清数据/覆盖安装的数据行为并写入文档。
- 统一备份覆盖 Android 媒体指针，跨设备恢复时明确标记"原图不在本机"。

GPX 导入、Route Segment 实体与 schema v2 迁移不在退出标准内，移到 Beta 0.3 之后（§6），给命名修正腾出时间。

### I3｜app.js 拆分与最小 SceneSlice（11-12 → 11-25）

- 只为 I4 拆路：从 `app.js` 拆出时间轴、飞行调度、底部卡片入口三个模块；每拆一块先补浏览器回归测试再移动代码。
- 定义 `SceneSlice(viewport, timeRange, scope)` 的最小版本：时间轴选择产出 SceneSlice，地点标记、路线与点亮按它裁剪；回放与其余图层后续迁移。
- 不改渲染画面；以现有截图/帧率测试为回归护栏。

### I4｜人生回放 v1（11-26 → 12-09）

- 时间轴两种模式：**人生**（居住阶段色带 + 旅程点，色带可起名）与 **年份**（保留现有筛选和年/月聚合）；阶段可重叠显示。
- 双向联动：时间轴选择驱动相机与 SceneSlice；地球上点城市/旅程反向定位时间轴与卡片。
- 统一播放器：阶段、年份、旅程都能播放、暂停、跳转、调速；阶段回放串联常驻城市、旅程与照片。
- 年度回顾与阶段回顾作为分享主入口，复用现有 Story 与分享面板；国内 Beta 期间以图片 / 静态 ZIP 为主，托管链接标注"境外服务"。

### I5｜首次使用收尾、性能与 Beta 试用（12-10 → 2027-01-05，含假期缓冲）

- 按 [PRODUCT.md](PRODUCT.md) 首次使用流程补齐：权限前隐私说明 → 扫描中城市逐个点亮 → 数字揭晓 → 自动约 20 秒回放 → 轻确认 → 按用户类型引导起名或年度回顾；量化"首次看到地球"时间。
- 持续使用：打开即增量导入并提示新旅程；居住地变化时提示给上一段起名。
- 定位并缓解瓦片冷加载卡顿；高山场景在中档机上的降级档位。
- 本地性能与崩溃记录（冷启动、帧间隔、内存），用户可选择上报。
- Beta 用户招募与反馈收集，按第 3 节退出标准做 0.3 验收，写验收记录，打 `v0.3.0`。

### 真机轨道（与 I2–I5 并行，依赖设备）

- 拿到设备后第一周：在 vivo 与一台中档机上跑 `connectedDebugAndroidTest`，再按 [BETA_0_3.md](BETA_0_3.md) 矩阵实测 1k / 5k+ 真实相册、HEIC、权限拒绝 / 部分授权、帧率、后台与杀进程续扫、IndexedDB 持久性。
- 同时采样真实照片的 EXIF 坐标，核实国产相机是否写入偏移坐标（白皮书 §13.3 第 3 条）。
- 设备到位越晚，I5 的验收越可能顺延；最晚在 I4 开始前拿到第一台，否则 `v0.3.0` 无法按期。

## 5. Public Beta 前的国内合规（Gate C / D 前置）

以下不进入 Beta 0.3 退出标准（Beta 用户为侧载安装的小范围试用），但要在 Beta 0.3 期间启动非工程部分，因为主体、备案和法务确认周期长。依据见白皮书 §13.3 与 §21.3。

| # | 事项 | 类型 | 前置 | 进入 |
|---|---|---|---|---|
| C1 | 确定运营主体（个人 / 企业） | 决策 | — | Beta 0.3 期间 |
| C2 | 隐私政策、个人信息与第三方 SDK 清单、行踪轨迹单独同意、导出与删除全部数据入口 | 法务 + 工程 | C1 | Gate C |
| C3 | 底图与审图方案：评估天地图等有审图号的服务，国界按标准地图；Esri 保留为境外版或可配置项 | 调研 + 工程 | — | Gate C |
| C4 | 境内分享托管：已备案域名、境内对象存储，手机号或微信登录；分享页在微信内置浏览器可用；海报优先 | 工程 | C1 | Gate C |
| C5 | APP 备案、软件著作权、隐私合规检测、各安卓商店开发者实名 | 行政 | C1、C2 | Gate C |

## 6. Beta 0.3 之后

按 Beta 数据决定优先级，候选方向：

- **Public Beta 准备**：§5 的 C2–C5 工程部分（境内分享、隐私流程、底图）。
- **P1 深化**：GPX 导入、Route Segment 实体与 schema v2（Chapter `parentId`，带迁移前自动备份与回滚测试）；Day/Place 完整视图；记忆（文字/语音）与照片的关联编辑；电影化回放镜头。
- **P2 产品化**：分享海报/短视频导出、可访问性、留存与分享漏斗、一次性解锁的付费实验（依赖 C7）；iOS（Capacitor + PhotoKit，先做可行性验证）。
- **3D 世界**：区域层默认开启、枝叶精细度、全球→近景衔接收尾。
- **P3**：仅在 Beta 证明有跨设备需求后启动快照同步（按 `CLOUD_SYNC.md` 的 CAS/三方合并设计，境内部署）；AI Life Narrator 在 Life Graph 与 Evidence 稳定后再接入（依赖 C8）。

## 7. 工作约定

- 每轮结束：合入 `main`、打标签、更新对应 `docs/` 验收记录；真机未测的项写明"未测"，不以模拟结果代替。
- 每项功能先补测试，再改实现；渲染相关改动必须附前后帧率记录。
- 新的用户可见推断都要带 Evidence 与来源标识，新编辑操作都要可撤销。
- 用户可见的国家、地区与地名一律经过国内口径映射；新增地名数据源时同步补映射与回归用例。
